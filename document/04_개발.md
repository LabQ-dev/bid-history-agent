# 04. 개발 — 구현 상세

## 1. 기술 스택

| 구분 | 선택 | 이유 |
|---|---|---|
| 언어 | Python 3 | 팀 친숙도, 표준 라이브러리만으로 웹 서버 가능 |
| 패키지 관리 | uv (`pyproject.toml`, `uv.lock`) | 재현 가능한 환경 |
| 외부 의존성 | `requests`, `openpyxl` 만 | API 호출과 엑셀 저장에만 필요. 웹 서버는 표준 lib |
| 웹 서버 | `http.server.ThreadingHTTPServer` | 프레임워크 없이 5개 엔드포인트면 충분 |
| 프런트엔드 | 순수 HTML/CSS/JS 단일 파일 | 빌드 없음, 서버가 그대로 서빙 |
| 저장소 | SQLite (표준 lib `sqlite3`) | 단일 파일, 설치 불필요, 파일 복사로 이전 |
| 배포 | Docker Compose / systemd | 상시 구동 + 자동 재시작 |

## 2. 모듈 구성

| 파일 | 역할 | 핵심 구현 |
|---|---|---|
| `bid_history/api.py` | OpenAPI 클라이언트 | `NaraClient`: 페이징(`paged`), 재시도(지수 백오프 3회), TPS 간격(0.05s), 30일 기간 분할(`date_chunks`), 오류 분류(게이트웨이/한도/자체오류), 키 마스킹 |
| `bid_history/search.py` | 검색 파이프라인 | `Query`(조건+`matches` 필터), `DetailCache`(SQLite), `sweep_bids`(공고 스윕), `search`(상세조회+필터+정렬) |
| `bid_history/report.py` | 출력 | `to_rows`(표 데이터 변환), 콘솔 표, `save_xlsx`/CSV (1위 하이라이트) |
| `main.py` | CLI 진입점 | argparse 옵션 파싱, `.env` 로드(`load_env`), 검색 실행 |
| `web.py` | 웹 서버 | 라우팅 5개, Basic Auth, 백그라운드 검색 스레드 + `job` 상태, 로그 핸들러 |
| `index.html` | 웹 UI | 검색 폼, `/api/status` 폴링, 결과 표 렌더, 엑셀 다운로드 |
| `collector.py` | 일일 수집기 | `collect`(멱등 적재), `--daemon`(매일 06시 루프), 백필 |

## 3. 구현상 주요 결정과 이유

### 3.1 API 호출 절약이 모든 설계를 관통한다
- 상세조회 1회 = 공고 1건. 기간 내 공고가 수천 건이면 하루 한도(1,000회)를 초과.
- 대응: ① 영구 캐시(개찰완료 데이터는 불변) ② 웹 검색 기본 300회/최대 500회 캡
  ③ 수집기 기본 800회 캡(웹 검색 몫을 남김) ④ 키워드·업무구분 필터로 스윕 축소
  ⑤ 한도 도달 시 중단하되 캐시 덕에 재실행이 이어서 진행.

### 3.2 웹 검색 = 백그라운드 스레드 + 폴링
- 검색이 수 분 걸릴 수 있어 요청-응답 한 번으로는 불가.
- WebSocket/SSE 대신 **단순 폴링** 선택: 표준 라이브러리 서버로 충분하고,
  팀 내부 도구라 폴링 오버헤드가 문제되지 않음.
- 진행 로그는 `bid_history` 로거에 커스텀 `logging.Handler`를 붙여 수집 —
  검색 로직에 UI 코드가 침투하지 않음.

### 3.3 동시 검색 1건 제한
- 전역 `job` 딕셔너리 + `threading.Lock`. 진행 중 POST는 409.
- 이유: 팀원 여럿이 동시에 검색하면 일일 한도가 순식간에 소진됨.

### 3.4 캐시 키 설계
- `bidNtceNo|bidNtceOrd|bidClsfcNo|rbidNo` — 공고번호만으로는 차수/분류/재입찰이
  구분되지 않아 4개 필드 조합을 키로 사용.

### 3.5 업체명 매칭
- 나라장터 등록명은 `주식회사 ○○`, `(주)○○`, `○○ 주식회사` 등 표기가 제각각
  → 법인격 표기·공백을 제거한 정규화 문자열로 부분일치 비교.

## 4. 환경 변수 (.env)

| 변수 | 기본값 | 설명 |
|---|---|---|
| `G2B_SERVICE_KEY` | (필수) | 공공데이터포털 인증키 (Decoding 키) |
| `WEB_HOST` | `127.0.0.1` | `0.0.0.0`이면 외부 접속 허용 |
| `WEB_PORT` | `8931` | 웹 포트 |
| `WEB_PASSWORD` | (없음) | 설정 시 Basic Auth 요구. 외부 접속 시 필수 권장 |
| `G2B_DATA_DIR` | 프로젝트 루트 | cache.db 위치 (도커에서 볼륨 경로로 지정) |
| `COLLECT_MAX_CALLS` | `800` | 수집기 일일 상세조회 한도 |
| `COLLECT_HOUR` | `6` | 데몬 수집 시각 |

## 5. 실행 방법 (개발)

```bash
uv sync                      # 의존성 설치
cp .env.example .env         # G2B_SERVICE_KEY 입력
uv run python web.py         # 웹: http://localhost:8931
python main.py --company "예신뷰" --from 20250101 --to 20250630 --types 용역
python collector.py --from 20260701 --to 20260731   # 백필
```

## 6. 코딩 컨벤션

- 주석·로그·오류 메시지는 한국어 (팀 내부 도구)
- 모듈 docstring에 "왜 이렇게 만들었는지"(API 제약 등)를 기록
- 사용자 대면 오류 메시지에는 반드시 **다음 행동 안내** 포함
  (예: "내일 다시 실행하면 캐시된 부분 이후부터 이어서 조회합니다")
